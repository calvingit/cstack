# 基础 Skills v0

日期：2026-10-29。范围：将提案及第一轮审查转为六个可独立读取的 Skill 源码，保持实验状态。

## 本轮选择

- 暂用六个阶段 Skill 作为入口与方法的最小组合，不另加命令层。是否应按方法拆分仍由后续任务评测决定。
- clarify/specify、design/decompose 各自内聚；diagnose 留在 BUILD；验证能力建设按需处理，不增设 verification-setup。
- 将必需规则内聚到各 Skill，允许少量重复，避免单独导入后引用断裂。没有 kernel.md 运行依赖、适配层、脚本执行器或持久状态。
- 默认保证验收依据独立；是否另需执行者由项目规则与风险决定。复用证据必须有明确依据，无法判断则补验或保留未知。
- VERIFY 分 AC、对象、环境表达结果，防止本地通过掩盖部署对象未知。REVIEW 审具体缺陷，默认三轮上限。SHIP 分开表达就绪、授权、实际结果，首版仅做到就绪判断。

## 验证边界

六个目录均运行 skill-creator 提供的 quick_validate.py，检查 frontmatter、必需字段与命名；检查生成的 UI 元数据及文件引用。结构通过只说明格式有效。

额外使用两个新上下文 Agent，显式要求读取实际 SKILL.md 并处理给定事实快照：VERIFY 的旧部署对象场景、SHIP 的旧审查和自动部署授权场景。输入不提供预期答案，禁止外部动作；这是文件加载与判断冒烟检查，不是实际执行验收，不是自动触发测试，也不是对照效果评测。保存输入、输出和 Skill 内容哈希于 evals/base-v0/smoke.json。

未验证：六阶段真实端到端任务、自动发现/正反触发率、各 Runtime 安装、多模型对照、真实 CI/合并/部署。没有据此宣称减少缺陷或改善成本。旧 example-v0 继续称为规则预实验，不计入 Skill 验证。

## 后续最小评测

固定本轮 Skill 内容哈希与实际加载记录；同任务、同模型、同工具和预算，比较原生 Agent、已加载 Skill、现有 calvingit/skills。先覆盖低风险直接改动、错误业务断言、真实对象错配、候选变化、审查误报及授权副作用。保存完整可取得的工具日志；缺失记录单独标明。路由与行为分别评分，避免只检查输出格式。
