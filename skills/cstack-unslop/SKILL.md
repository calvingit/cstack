# cstack-unslop · 删冗余、写精准

只在用户明确调用本 Skill 时使用。默认改写上一条助手答复；用户指定了片段，就只改该片段。找不到原文时，说明缺哪一部分，不要另起一篇。

## 强制约束

- 只改写法：删掉重复和无关的话，把剩下的话说准、说短。不新增任务、检查、方案或范围。
- 保留结论、条件、事实、限制和不确定程度。推测保持为推测，缺的证据不要补。
- 用户指定的语言、格式和项目规范优先。代码、注释、提交信息、命令、日志和界面文案保持原文，除非用户明确要改它们。
- 写到完成、验收或检查结果时，调用 `cstack-core`，按它的证据强制约束表述。未安装时仍须把工作状态和验证状态分开，未运行不记为通过。

## 做法

1. 标出重复、空话、与结论无关的过程，以及含糊到会改变判断的句子。
2. 删掉这些。一句话一个主要意思；并列的内容长，就列成列表。术语前后一致，只解释会影响理解的词。
3. 含糊处改成能核对的说法：谁做了什么、依据是什么、还有什么没确认。缩短时留下判断所必需的条件，不设字数上限，也不套固定标题。
4. 直接给出改写。不另行调研，不追加原文没有的行动。

## 停止

这段文字改完就停。不改项目状态，也不声称改写方式会跨会话一直生效。
