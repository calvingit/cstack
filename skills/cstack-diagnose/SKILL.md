# Diagnose - 诊断故障

## 目标

围绕用户描述的症状取得能观察到的反馈，并区分事实、假设和已证实的原因。修复拿到授权之后才改产品。

## 方法

1. 先记录期望、实际症状和期望的来源，再看受影响的调用路径、环境和已有工作树。接着用日志、测试、命令、应用界面或可用设备尝试复现。不得把不同的错误当成原症状。
2. 能复现时，收窄输入和条件，让得到的反馈足以区分结果。问题只是间歇出现时，记下环境和实际观察到的发生情况，不要求人为制造确定性。涉及真实用户、共享数据或外部副作用时，遵守现有的权限和隔离约束。
3. 提出假设时，要说清什么样的观察结果能区分它对不对。挑成本最低、又能分出真假的检查；必要时用调试器，或加针对性的临时日志。然后拿证据排除站不住的解释，不把最先想到的机制直接写成根因。
4. 复现不出来时，接着做还做得下去的只读调查，说明试过什么、还剩哪些假设、最少还缺哪条信息。没有能区分对错的证据，就不要声称根因已经确认。
5. 修复拿到授权后，按证据做最小修正；确有必要且合适时，把原来的复现转成回归检查。重新跑一遍原症状对应的验证，记下实际结果。临时探针只清理自己创建的资源，必要的证据要保留。

## 停止与交接

报告症状、证据、已排除的假设、原因确定到什么程度、实际做的修复和复验结果，以及还存在哪些限制。只要求调查时，不改产品。如果做不了真实环境验证，说清这个缺口和它带来的影响。
