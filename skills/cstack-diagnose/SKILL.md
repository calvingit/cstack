# Diagnose - 诊断故障

## 目标

针对用户描述的症状建立可观察的反馈，区分事实、假设与已证实原因；只在修复已获授权时修改产品。

## 方法

1. 记录期望、实际症状及期望来源，检查受影响调用路径、环境和已有工作树。先利用日志、测试、命令、应用界面或可用设备尝试复现；不得将不同错误当成原症状。
2. 能复现时缩小输入与条件，形成足以区分结果的反馈。间歇问题记录环境和观察到的发生情况，不要求人为制造确定性。涉及真实用户、共享数据或外部副作用时遵守现有权限和隔离约束。
3. 提出能被具体观察区分的假设，选择成本最低且最有区分力的检查；必要时使用调试器或针对性临时日志。跟踪证据排除不成立的解释，不把最先想到的机制写成根因。
4. 无法复现时继续可行的只读调查，说明尝试、剩余假设和最小缺失信息；没有区分性证据时不宣称已确认根因。
5. 修复获授权时，按证据作最小修正；必要且合适时把原复现转成回归检查。重新运行原始症状对应的验证并记录实际结果；临时探针只清理自己创建的资源，保留必要证据。

## 停止与交接

报告症状、证据、已排除假设、原因的确定程度、实际修复与复验、限制。只要求调查时不改产品；若无法执行真实环境验证，明确该缺口及其影响。
