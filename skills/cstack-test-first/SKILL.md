# Test First - 测试先行

## 目标

用小步反馈，把一个已确认的行为或一个已定位的回归实现出来。测试保护行为，不能代替完整的交付验收。

## 方法

1. 从需求、公开契约、业务规则或独立算例出发，定下一个能观察到的预期，再看现有测试是否已经保护了它。复制实现算法、扩大 mock 范围、仅确认内部调用次数，这些都不能自动证明预期正确。
2. 选择真实调用方实际使用的合适边界，测试层级取最低、但足够的那一层，并说明替身屏蔽了什么。不要仅为测试暴露内部状态，也不要增加在生产中不承担职责的接口。
3. 写一个聚焦的失败检查，实际跑一遍。确认这次失败对应的是目标行为，而不是语法、测试环境或无关错误。如果一开始就通过了，先调查，不要声称完成了失败步骤。
4. 做出最小但正确的实现，再跑同一个检查，确认它通过。需要改善时，只重构当前范围内的代码，然后重跑受影响的检查。按行为逐个推进，不要按代码行数或示例数量机械地生成测试。
5. 反馈回路不适用，或者代价太高时，说明有哪些限制，改用当前任务允许、也足够的替代检查。不要为了走完流程去改业务期望或生产设计。

## 停止与交接

报告要写清楚：做的是哪个行为，预期从哪来，实际失败和实际通过各跑了什么命令、观察到什么，改了哪些代码，还有覆盖上的限制。没有实际的失败或通过记录时，说明缺了哪几步。TDD 的结果不自动构成对所有验收条件（AC）、真实外部系统和视觉效果的验收。
