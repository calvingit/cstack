# 测试先行

## 目标

用小步反馈实现一个已确认的行为或已定位的回归。测试保护行为，不代替完整交付验收。

## 方法

1. 从需求、公开契约、业务规则或独立算例确定一个可观察预期，查看现有测试是否已经保护它。复制实现算法、扩大 mock 或仅确认内部调用次数不能自动证明预期正确。
2. 选择真实调用方使用的合适边界和最低足够的测试层级，说明替身屏蔽了什么。不要仅为测试暴露内部状态或增加没有生产职责的接口。
3. 写一个聚焦的失败检查并实际运行。确认失败对应目标行为，而非语法、测试环境或无关错误；如果起初已通过，先调查，不声称完成了失败步骤。
4. 做出最小正确实现，再运行同一检查确认通过。需要改善时只重构当前范围，再运行受影响检查；逐个行为继续，不按代码行数或示例数量机械生成测试。
5. 如果反馈回路不适用或成本过高，说明限制，采用当前任务允许且足够的替代检查；不要为满足流程改变业务期望或生产设计。

## 停止与交接

报告行为、预期来源、实际失败与通过的命令及观察、代码变更和覆盖限制。没有实际失败或通过记录时说明所缺步骤；TDD 结果不自动构成所有 AC、真实外部系统或视觉效果的验收。
