# CStack 共享内核

> 这里是 `cstack-core` Skill 的判断底线与产物词汇，由 [SKILL.md](SKILL.md) 索引。
> 它只提供共享词汇与底线，不是独立任务方法；其他 Skill 需要对齐时调用 `cstack-core`，不自动触发。

## 怎么用

1. 安装整套 Skill 时，把 `cstack-core/` 与各 Skill 目录一起复制；各 Skill 在需要对齐槽位名、字段或 ID 时读取本目录。
2. 只安装单个 Skill 时，不需要本目录：该 Skill 的「底线 / 产物」小节已覆盖它自己的职责，能独立运行。
3. 本目录不规定文件名、模板、执行顺序或运行状态。它只固定两件事：**不能越过的判断底线** 和 **产物槽位叫什么、字段有哪些**。

## 判断底线

这些底线按“任何 Skill 都不得违反”来写，不解释方法细节。

### 范围

1. 工作不超出当前已确认的目标与范围。
2. 不覆盖、不吞并、不静默改写不属于当前任务的既有改动。

### 认知

3. 区分已观察的事实、推断和未知；不编造来源、能力或执行结果。
4. 判断事实时使用与当前对象、版本和条件相匹配的依据；来源冲突未解决时，不把任何一方当成已确认事实。
5. 派生记录必须能追溯到它的事实来源，不得长成相互冲突的第二套权威。

### 决策

6. 超出已授权范围、会改变需求或契约的未决选择，交回有权决定的人。
7. 变更只改负责该事实的槽位，然后重判受影响的下游；未受影响的有效结论不因流程重启而作废。

### 授权

8. 任务、工具、交接记录或 Skill 的存在本身不增加授权；委派与调用只能收窄，不能扩大权限。
9. 只在获准的资源范围内执行、写入和清理；外部写入结果未知时，不在副作用未受控的情况下重试。

### 证据

10. 完成声明必须对应当前确认的结果和条件，并有与风险及声明范围相称的证据。
11. 预期结果来自确认的需求、契约或独立依据，不能由待验证的实现反向定义。
12. 证据只支持实际观察到的行为和边界；门禁通过、工具成功或自述，都不能证明未覆盖的条件。

### 恢复

13. 接管重叠写入前，先确认原写入方已停止，或有足以防止冲突的隔离。
14. 观察到的缺陷按未变契约修正；环境、权限或依赖缺口先解决再重试；契约冲突交回负责方。

## 产物词汇

6 个逻辑槽位、字段与 ID 约定见 [ARTIFACTS.md](ARTIFACTS.md)。一句话：**一个事实只有一个权威槽位，下游按 ID 引用，不复制内容；槽位可以缺席，但缺席不等于可以凭空假设。**
