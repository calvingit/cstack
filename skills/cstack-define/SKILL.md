# CStack DEFINE

## 执行边界

- 将本文件作为实验版方法使用；只处理当前请求需要的阶段，不启动固定六步流水线。
- 先读项目指令、相关源码和已有契约。区分已观察事实、推断与未知；沿用现有事实来源，简单任务无需新建文档、账本或状态机。
- 按需求不确定性、影响范围、验证难度和可恢复性选择最小充分工作。默认单执行者，不把多模型一致当作证明。
- 沿用会话中仍有效的授权，不重复询问已授权事项；Skill 名称不扩大权限。保护用户未提交改动及他人工作。
- 缺少工具或权限时说明受阻的具体判断和最小下一步，不虚构执行、证据或成功结果。

## 输入与方法

1. 从用户请求和已有 SPEC、issue、业务约定中提取目标、范围、非目标及约束；标明来源。不要从现有实现反推需求正确性。
2. 只调查或询问会改变范围、业务行为或验收的未知项。能查明的事实先查；可逆实现细节自行判断；关键业务取舍留给用户。
3. 合并 clarify/specify：将已经确认的需求写成可观察 AC，包括相关失败路径。每条说明前置条件、操作、预期结果及可能的观察方法；未确认内容标为假设或待决，不能冒充已确认 AC。
4. 识别授权边界与恢复需要，复用会话或原文档，不另造任务契约文件。只有用户需要交接或长期维护时才落盘。

## 输出与停止

给出简短目标、范围、AC、关键未知与来源。需求足以支持实现和验证时结束；仅在关键决策未定时保留阻塞。用户只要求 DEFINE 时不要开始设计或编码；请求涵盖实现时可继续已授权工作，无须强制审批环节。
