# cstack-retro · 复盘工程工作

## 强制约束

- 先定范围；只读当前会话和用户授权访问的记录，不默认扫其他项目或历史会话。
- 事实、原因推断和未知分开；记录缺失时，不推断某个 Skill 是否触发或生效。
- 一次性失误不自动变成通用规则；不默认新增 Skill。
- 复盘默认只给建议；实施需要授权。

## 产物

- **读**：当前会话、授权记录、实际命令 / 结果 / 反馈。
- **写**：复盘记录（问题或有效做法、证据、建议、预期作用、限制）。它不是正式产物；长期发现按“往哪写”分流。
- 需要与其他 Skill 统一产物命名和字段时，调用 `cstack-core` Skill；未安装时以本节作为最小可用版本。

## 目标

从可核查的操作、结果和反馈里，找出影响交付的具体问题或有效做法，提出最小改进。

## 分析

- 找具体问题或有效做法，区分事实、推断和未知。
- **同一类错误出现两次才算类别**；单个失误不立规则。
- 能修在更高层就修：架构消除 > 类型 / lint / CI 拦截 > 测试 > 文档或规则。文档是最后手段，因为跳过它不会失败。
- 新检查要能拦住一个真实发生过的旧错误；否则只是“我觉得有用”。
- 维护规则表：被纠正时修错误并加规则；如果规则早就有却没有机制执行，同类错误再犯就是重犯，应把修复手段升到更高层；错误不可能再发生时删掉规则。

## 长期知识往哪写

只保留真正值得长期保留的发现，并交给负责方：能由测试或注释完整承载的就写那里；否则写项目已有的 runbook、领域文档或 ADR；不新建固定文件名，也不另造第二份权威。

## 报告与停止

按影响给证据、建议和预期作用；说明样本、环境和限制。复盘本身不改产品、不建新 Skill、不改规则，除非获授权；实施后报告实际验证结果。会话观察能发现问题，但观察本身不能证明 Skill 带来收益；效果比较要在目标 Harness 取得可比证据。
