# 复盘工程工作

1. 确定复盘范围，读取当前会话及用户指定或授权访问的记录；不默认扫描其他项目或历史会话。
2. 从可核查的操作、结果和反馈中找出影响交付的具体问题或有效做法，区分事实、原因推断和未知。记录缺失时不推断某个 Skill 是否触发或生效。
3. 针对值得处理的问题，先检查已有工具、项目指引和验证方式，再建议最小改进；一次性失误不自动变成通用规则，也不默认新增 Skill。
4. 按影响说明证据、建议及预期作用。复盘请求默认只给建议；用户已要求实施时，按授权修改并报告实际验证。

会话观察可以发现问题，但不能单独证明 Skill 带来了收益；涉及效果比较时，说明还需在目标 Harness 中取得可比证据。
