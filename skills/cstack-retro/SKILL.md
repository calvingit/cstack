# Retro - 复盘工程工作

1. 先定下复盘范围：读当前会话，以及用户指定或授权访问的记录。其他项目或历史会话不默认扫描。
2. 从可核查的操作、结果和反馈里找出影响交付的具体问题或有效做法。事实、原因推断和未知要分开。记录缺失时，不推断某个 Skill 是否触发或生效。
3. 值得处理的问题，先看已有工具、项目指引和验证方式，再给出最小改进建议。一次性的失误不自动变成通用规则，也不默认新增 Skill。
4. 证据、建议和预期作用，都按影响大小来说。复盘请求默认只给建议。用户已经要求实施时，才按授权修改，并报告实际验证的结果。

会话观察能发现问题，但观察本身不能单独证明 Skill 带来了收益。涉及效果比较时，说明还需要在目标 Harness 中取得可比证据。
