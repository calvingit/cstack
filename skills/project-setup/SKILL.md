# Project Setup - 记录项目工程档案

## 强制约束

- 只记录**稳定的项目事实**；不存当前任务、运行结果、授权、命令或模型选择。
- 已有来源优先，不复制；不假定固定路径；不创建空脚手架。
- 写入前展示检测依据和拟写内容，确认后再写。
- 配置本身不授予提交、推送或外部发布权限。

## 产物

- **读**：AGENTS / README / CONTRIBUTING、现有任务约定、领域与架构文档、验证入口、Git 状态。
- **写**：PROFILE——术语表 / 领域模型位置、验证入口、需求权威来源、既有架构决策（ADR）位置、任务文档存放约定。默认放项目已有的工程档案位置（如 `.agents/profile.md`）；`AGENTS.md` 只放链接与读取条件。
- 需要与其他 Skill 统一产物命名和字段时，调用 `core` Skill；未安装时以本节作为最小可用版本。

## 目标

让后续 Skill 能按需定位项目事实，而不是每次重新发现，也不再各自维护一份过期副本。

## 发现

- 读适用指令、Git 状态、README、现有任务约定、领域与架构文档、需求来源、验证指南和协作规则。
- 把候选标为 confirmed / inferred / missing / conflicting；目录或工具存在，不等于有权威或真的可用。

## 只记录稳定事实

- 记录位置与策略：术语表在哪、验证入口是什么、需求权威来源是哪一种、ADR 放哪、任务文档放哪。
- 不记录当前需求、任务状态、运行结果、具体命令、Agent / 模型选择或 Git 权限。
- 具体验证方法留在现有指南或本地验证资料里；PROFILE 只放链接与摘要。
- 不预建空的任务目录、术语表、ADR 或验证 Harness 脚手架。

## 写入

1. 展示检测依据、拟写 PROFILE、`AGENTS.md` 条目，以及需要迁移的旧配置。
2. 已有明确值沿用；仓库证据无法确定的重大选择问一次；调用方已给的确认不再重复问。
3. 迁移旧的内嵌配置时，保留确认值与未知字段，然后移除旧块，不留下两份活跃副本。
4. 重复设置同一配置应等同于空操作，不产生重复条目或仅格式上的变化。
5. 重读改动文件，核对路径和链接，检查 diff。

## 停止与报告

报告变更条目、迁移情况、确认值、留给后续发现的项，以及未解决的冲突。文件存在不代表 Runtime 已加载它，也不代表验证方法已经实际运行过。不提交、不推送，除非获授权。
