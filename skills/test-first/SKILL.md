# Test First - 测试先行

## 硬约束

- 测试保护行为，不替代完整验收。
- 预期来自需求、公开契约、业务规则或独立算例，不复制实现算法。
- 一个行为一个循环；不按覆盖率或示例数量批量造测试。
- 不为测试方便而暴露生产内部。

## 产物

- **读**：SPEC（`R#` / `AC#`）、TECH（`D#`，若存在）、现有测试与验证方法。
- **写**：代码 + 测试 + 实际 red / green 记录（执行者标为实现者）；不写正式 `EVIDENCE`。
- 需要与其他 Skill 统一槽位名和字段时，调用 `core` Skill；未安装时以本节作为最小可用版本。

## 目标

用小步反馈，把一个已确认行为或一个已定位的回归实现出来。

## 准备

- 选定行为与独立预期来源；找真实调用方使用的生产接口，以及需要替身的外部依赖。
- 选最小但足够的测试层级，并说明它不能证明什么。
- 复用已有决策与接口；新行为只要有真实调用方依据就可以开始，不必等接口已经实现。

## 有用测试

- 保护确认契约、领域规则、有意义的失败模式或已知回归。
- 设想两种改动来判断：改坏行为时测试应变红；只调整内部实现时仍应保持绿色。
- 场景 / 例子 ≠ 测试数量；按行为风险选择，不机械地一个例子一个测试。
- 没拿到反馈前，不要一次写一大批测试，替尚未验证的接口背书。

## Red → Green → Refactor

1. **选一个行为**：写下可观察预期，先看现有测试是否已经保护它。
2. **Red**：写最小失败测试并实际运行，确认失败来自目标行为缺失或错误，不是 fixture、环境或无关语法。已经绿就先调查，不声称完成了失败步骤。
3. **Green**：做最简单、正确的实现。
4. **Refactor**：有必要时只重构被触动的代码，行为不变，重跑测试和最小受影响集合。
5. 继续下一个行为；共享设计变化或无关清理超出本循环，交回调用方。

缺陷修复：复用已经最小化的复现，先转成回归测试，再修复，最后复跑原始复现。

## 停止与报告

报告覆盖的行为、预期来源、实际 red / green 的命令与观察、本次范围内的重构、剩余缺口。不能跑就说，不声称完成循环；不放宽预期求绿。反馈回路不适用或代价太高时，说明限制并用相称的替代检查。TDD 结果不构成对所有 AC、真实外部系统和视觉效果的验收。
