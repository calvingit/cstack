# Wayfinding - 跨会话找路

## 硬约束

- 规划，不直接做：每张决策工单只处理一个决策；地图在通往目的地的路清楚时结束。
- 不在地图之外擅自扩大范围；超出目的地的内容属于 Out of scope，不是迷雾。
- 一次会话最多关闭一张决策工单；research 类工单可以并行派发。
- 地图与工单是共享记录，不是新的运行状态机。

## 产物

- **读**：松散想法、项目现状、已有文档与 ADR。
- **写**：MAP（Destination、Notes、Decisions so far、Not yet specified、Out of scope）和决策工单（Question、类型、blocked-by）。沿用项目已有的任务系统或跟踪工具；不建第二套状态。
- 需要与其他 Skill 统一槽位名和字段时，调用 `core` Skill；未安装时以本节作为最小可用版本。

## 目标

把跨会话的大工作画成一张共享地图，一次解决一个决策，直到通往目的地的路清楚。

## 地图

- **Destination**：到达终点是什么样（一份 SPEC、一个已经确定的决策，或一次就地改动），一两行；每次会话先确认。
- **Notes**：领域、需要咨询的 Skill、长期偏好。
- **Decisions so far**：已关闭工单的索引，一行摘要加链接，不重复细节。
- **Not yet specified（战争迷雾）**：知道要来、但现在还说不清的决策；能说清问题才升成工单。
- **Out of scope**：明确排除的工作，不再转为工单。

## 决策工单类型

- **research**（AFK）：查阅资料，查清决策所依赖的事实。
- **prototype**（HITL）：做一个粗糙但具体的原型，让讨论更接近实际。
- **grilling**（HITL）：通过对话达成决策，调用 `clarify`。
- **task**（HITL / AFK）：为解锁决策必须先做的手工工作。

## 前沿与阻塞

- 工单声明 blocked-by；无阻塞且无人认领的工单构成前沿。
- 认领：先标记归属，再做，支持多会话并行。
- 迷雾只在通往目的地的方向上聚集：能说清问题就建工单，不能就留在 Not yet specified，不提前切片。

## 两种调用

- **画图**：命名目的地（用 `clarify` / `domain-model`）→ 广度扫描，找出迷雾 → 建地图 → 把现在能说清的问题建成工单，并标出依赖关系 → 并行跑 research 类工单 → 停。
- **推进**：先看地图概览 → 选一张前沿工单并认领 → 处理（按 Notes 调用对应 Skill）→ 记录答案、关闭工单、更新 Decisions so far、把新近能说清的迷雾升级为工单。

## 停止与交接

规划本身不授权实现；目的地到达后交给 `specify` / `design` / `slice`。不建立与项目 issue / tracker 并行的持久状态。
