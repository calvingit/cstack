# 表达示例

以下都是虚构的说明场景，不是任何项目的实际行为，也不是运行证据。

## 对话内解释

用户要求理解一个缓存的失效条件，并希望切换不同情况。先确认规则及来源；当宿主的 `visualize` 可用于该请求时，调用它，提供可切换的条件和对应结果。规则有未知时在图中或图旁标明；不补造缓存命中率。

## 解释一次变更

用户要求图形化解释一个 PR。读取实际 diff、目标分支和必要调用方，再挑选能表现前后区别的视图，例如一张数据流图和一个接口字段对照。把未观察到的行为留为未知。需要把说明放入 PR 文案时，输出目标平台支持的可复制内容；未经授权不发布。

## 没有原生 visualize

用户要求解释队列状态变化。若宿主没有原生 `visualize`，优先选择可渲染的状态图；若用户还希望试不同输入并观察状态变化，可提供单文件交互页面，并如实说明是否实际预览和测试过。图形表达不等于系统已经实现或验证该状态机。
