# 表达示例

下面的场景都是虚构的说明例子，不代表任何项目的实际行为，也不能当作运行证据。

## 对话内解释

用户想弄懂一个缓存什么时候失效，还希望能切换不同情况来看。先确认规则和它的来源。宿主的 `visualize` 适合这个请求时，就调用它，给出能切换的条件和对应的结果。规则里有不明白的地方，就在图中或图旁标出来。不要凭空编一个缓存命中率。

## 解释一次变更

用户要求用图解释一个 PR。先读实际的 diff、目标分支和必要的调用方，再挑能看出前后区别的视图，比如一张数据流图，再加一个接口字段对照。没观察到的行为，就留作未知。需要把说明放进 PR 文案时，输出目标平台能复制的形式。没有授权就不要发布。

## 没有原生 visualize

用户要求解释队列状态怎么变化。如果宿主没有原生 `visualize`，优先选一个能渲染的状态图。如果用户还想换不同输入、看状态怎么变，可以给一个单文件的交互页面，并如实说明有没有真的预览和测试过。图画出来，不等于系统已经实现或验证过这个状态机。
