# cstack-rewrite · 改写表达

## 目标

把上一条助手答复或用户指定的片段改成读者更容易理解的版本：更通俗，或更精炼。只改写法，不改原意、结论、条件、依据和不确定程度。

## 范围与模式

- 默认重述上一条助手答复；用户指定片段时只以该片段为范围。找不到原文时，说明缺的是哪一部分，不要猜原答案。
- 用户指定模式就照办；没有指定时按请求判断：
  - **通俗**：降低理解门槛，术语和数字保留并解释清楚。
  - **精炼**：删掉重复和无关过程，把剩下的话说准、说短。
- 两种模式同时被要求时，先精炼再解释必要术语；冲突时以用户最后一次指定为准。

## 强制约束

- 只改写法：不新增任务、检查、方案或行动建议，不重新调研。
- 保留原文的结论、条件、事实依据、限制和不确定程度；推测保持为推测，缺的证据不要补。
- 必要的术语、数字、命令或引用保留下来，并解释清楚。
- 举例只为帮助理解，要说清它只是举例，不能当作新证据。
- 用户指定的语言、格式和项目规范优先。代码、注释、提交信息、命令、日志和界面文案保持原文，除非用户明确要改它们。
- 涉及完成、验收或检查结果的表述时，读取 `cstack-core` 的 `PRINCIPLES.md`「证据」一节并按其要求写：分开写工作状态和验证状态，未运行不记为通过。未安装时仍须满足这条要求。

## 改写步骤

1. 标出重复、空泛表述、与结论无关的过程，以及含糊到会改变判断的句子。
2. 按模式处理：通俗模式替换读者不熟的表达、补必要背景；精炼模式删除冗余，一句话一个主要意思，并列内容长就列成列表。
3. 把含糊的表述改成能核对的说法：谁做了什么、依据是什么、还有什么没确认。缩短时留下判断所必需的条件，不设字数上限，也不套固定标题。
4. 直接给出改写结果，不复述原文。

## 停止与边界

改写完成即停止。不改项目状态，也不声称改写方式会跨会话一直生效。
