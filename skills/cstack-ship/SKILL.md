# CStack SHIP

## 执行边界

- 将本文件作为实验版方法使用；只处理当前请求需要的阶段，不启动固定六步流水线。
- 先读项目指令、相关源码和已有契约。区分已观察事实、推断与未知；沿用现有事实来源，简单任务无需新建文档、账本或状态机。
- 按需求不确定性、影响范围、验证难度和可恢复性选择最小充分工作。默认单执行者，不把多模型一致当作证明。
- 沿用会话中仍有效的授权，不重复询问已授权事项；Skill 名称不扩大权限。保护用户未提交改动及他人工作。
- 缺少工具或权限时说明受阻的具体判断和最小下一步，不虚构执行、证据或成功结果。

## 输入与方法

1. 锁定判断对象、目标分支或发布环境、当前候选与基线。读取真实项目门禁、CI、审查、验收证据和已有授权；缺少平台访问不能猜测保护规则或审批状态。
2. 核对证据的 AC、实际受测对象/产物来源、环境、检查覆盖和候选映射。旧 HEAD、变化的基线、测试/配置/环境变化均需判断影响。组合提交检查须核对父提交及目标；平台绿色、skipped/neutral 或模型共识不能替代 AC 证据。
3. 分开判断 Merge Readiness 与 Release Readiness。合并会自动部署时，检查部署条件与副作用授权；不能把合并授权扩展成未获准的生产操作。无法确定自动动作时说明缺口。
4. 核对实质缺陷、未验证关键行为、项目所需审批/检查、冲突与恢复能力。列出剩余风险及明确接受者；风险接受不把 FAIL/NOT VERIFIED 改为 PASS，不绕过项目硬性门禁。
5. 最后重新读取可取得的候选与关键条件，说明结论时点。无法取得原子约束时，不承诺判断对未来执行持续有效。将来执行者应重新核对候选并利用平台预期 SHA 或等价保护；条件变化须重新判断。

## 输出与停止

分别报告：
- 就绪：指定候选/目标的 Merge GO 或 HOLD；需要发布时另列 Release GO 或 HOLD，未评估发布则明确写未评估。必要证据或硬门禁缺失为 HOLD。
- 授权：已获准的具体动作、对象、条件与未授权副作用。GO 可以与未获执行授权同时成立，无需为完成只读判断索要执行许可。
- 阻塞与恢复：事实、未知、剩余风险、补证据/修复的最小下一步及适用恢复方案。
- 执行结果：本 Skill 未执行交付。若引用外部动作结果，核对真实状态；排队不等于已合并，已合并不等于已部署。

在就绪判断处停止。本实验版不提供执行交付能力，即使已有授权也不在本 Skill 内执行；需要交付时清楚交接给另行授权的工具流程，不能声称已完成动作。
