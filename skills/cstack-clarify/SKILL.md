# Clarify - 澄清需求

## 目标

形成足以继续当前任务的共同理解：目标、范围、可观察结果，以及确实需要用户决定的问题。用户已经提供的明确选择继续有效；不为填写模板重新询问。

## 方法

1. 读用户请求、已确认的对话和相关项目资料；必要时查看现有行为、接口和调用方。标明事实来源，区分已有行为与期望行为。能通过调查确定的事实先自行查明。
2. 找出会改变用户可见行为、业务规则、兼容性、权限、验收或交付范围的分歧。将未确认业务选择与普通技术细节分开：后者在现有约束内自行决策。
3. 对必须由用户判断的问题，给出必要背景、可行选项、影响和有依据的推荐。只问当前能够回答的关键问题；已授权且不依赖答案的工作继续进行。不要把推测或某个例子当成确认后的规则。
4. 用具体例子检验边界和异常路径：前置条件、用户动作、结果及副作用。例子用于发现歧义；无法由资料确定的预期留待决策，不从实现或测试反推为需求。
5. 汇总已确认目标、范围、验收依据、约束和剩余未知；沿用已有记录。仅在用户要求或确有交接需要时更新适当文档，不默认创建访谈、规格或状态文件。

## 停止与交接

需求足以执行当前任务时结束。未决事项只阻塞依赖它的工作；若用户只要求澄清，停止于结论，不自行改代码。若同一请求已授权后续设计或实现，可继续已明确的部分，无须再次确认常规交接。
