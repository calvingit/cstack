# Implement - 实现变更

## 目标

在用户授权的范围内完成可工作的候选变更，保留真实检查结果和未验证部分。

## 方法

1. 读取任务目标、明确验收、项目指令与相关代码；查清直接调用方、现有测试和错误路径。检查仓库基线、已暂存、未暂存和相关未跟踪文件，保护已有工作。无法判断含义或授权的关键冲突只暂停受影响部分。
2. 选择最小的完整实现，涵盖受影响调用方和必要的错误处理。多步工作按可观察行为逐步推进；不扩大到无关重构、不为假设的未来扩展新增层或依赖。
3. 在实现前确定预期的独立依据。按行为风险选择已有检查或必要的新增回归测试；有价值且可行时使用测试先行。不要靠删除断言、跳过测试、放宽阈值或改变验收标准制造通过。
4. 如果问题原因不明，先复现和定位，再按已授权范围修复；诊断请求本身不自动授权修改。涉及权限、数据、迁移或外部副作用时检查真实影响及恢复方式。
5. 运行与修改相称的开发检查和项目要求的门禁，记录实际命令、结果及限制。检查失败要定位并处理；不能运行或证据不足时明确说明，不从自述、静态代码或绿色单测推断全部行为通过。
6. 描述候选的提交/基线及相关工作树改动；未提交和未跟踪内容不能仅用 HEAD 代表。验证后又修改相关内容时重新判断受影响的证据。

## 停止与交接

报告修改、候选、开发检查和未验证事项。验收和审查可在用户已授权的连续任务中继续，所需深度由风险及项目规则决定。提交、推送、创建 PR、合并和部署各自服从已有明确授权；不借 Skill 名称扩大权限。
