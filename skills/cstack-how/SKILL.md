# How - 解释代码如何工作

只在用户明确调用本 Skill 时使用。先确定用户指定的范围和运行入口。然后读项目指令、实际源码和必要的配置。范围不明确时，只查足以确定目标的上下文。

从入口开始，追踪相关调用方、控制流、数据变化和状态变化、外部依赖，以及关键错误路径。读测试有助于理解预期，但不能仅凭测试推断生产路径。没有实际运行，就不要描述成运行观察。

解释关键步骤、职责和条件时，用用户需要的抽象层次，并引用可核对的文件或符号。分清楚哪些行为是源码直接证明的，哪些是合理推断，哪些还没查清。缺失路径不要猜。

回答完当前实现如何工作，就停止。历史动机、故障根因和目标重构，属于其他问题。此操作不修改代码、配置或状态。
