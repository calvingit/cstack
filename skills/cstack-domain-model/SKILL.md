# Domain Model - 梳理领域模型

1. 先确定这次要理清的业务范围，以及讨论要达到什么目标。再读已确认的需求和现有资料，必要的代码也要看。然后分清用户的期望、当前的实现，以及还没定下来的规则。
2. 找出会影响当前问题的概念、关系、状态和业务约束。碰上含义不同或容易混淆的术语，用具体场景讲清楚。只引入有助于理解和决策的模型，不预设架构风格。
3. 对照已有代码和文档，指出术语或行为上的冲突，并给出证据。业务意图不能从现有实现里自行推断。重要规则如果还没定，又会影响行为，该问的就要问；其余合理的假设注明即可。
4. 把已经确认的概念、规则和还没定的事项汇总起来。记录位置按用户的请求来，或者放到项目已有的位置。只做建模时，不自动创建术语表、ADR，也不自动改代码。后续实现按已有的授权继续。
