# Performance - 分析性能

1. 先弄清用户关心哪个场景、哪些指标，目标是什么。再读相关实现和已有的测量。记下候选、设备或环境、构建模式、数据规模和负载。不具可比性的结果不要直接放在一起比较。
2. 在安全且已获准的条件下复现问题，建立基线。用哪种数据按问题挑：计时、性能分析或运行数据，哪个可用就用哪个。需要时重复测量，把波动一并记下。确实测不了，就说明缺口在哪，不要猜瓶颈，也不要声称有改进。
3. 顺着观察到的现象收窄范围，把相关现象、瓶颈假设和已有证据支持的原因分开。挑一个最小的检查，只要能区分这些假设就行。不要预设问题一定出在 UI、网络、数据库或某个框架上。
4. 用户要求优化时，才在授权范围内针对瓶颈动手改。改完以可比条件复测，并检查受影响的功能。用户只有分析要求时，保持只读。
5. 报告要写清指标、环境、基线与复测结果、实际变更和限制。差异落在测量波动之内，或者前后条件不一致，就不要宣称性能提升。
