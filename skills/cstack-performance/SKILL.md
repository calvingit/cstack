# 分析性能

1. 确定用户关心的场景、指标和目标；读取相关实现及已有测量。记录候选、设备或环境、构建模式、数据规模和负载，避免把不具可比性的结果直接比较。
2. 在安全且获准的条件下复现并建立基线。按问题选择可用的计时、性能分析或运行数据；需要时重复测量并记录波动。无法测量时说明缺口，不猜测瓶颈或宣称改进。
3. 根据观察缩小范围，区分相关现象、瓶颈假设和已得到证据支持的原因。选择能区分假设的最小检查；不要预设问题一定在 UI、网络、数据库或某个框架。
4. 用户要求优化时，在授权范围内针对瓶颈修改；以可比条件复测，并检查受影响的功能。只要求分析时保持只读。
5. 报告指标、环境、基线与复测结果、实际变更和限制；差异落在测量波动内或条件不一致时，不宣称性能提升。
