# Design - 设计技术方案

## 目标

把当前工作里必须共享、或者不可轻易撤回的技术决策定下来，让实现和验证有可靠的依据。局部改动不值得另造一层设计。

## 方法

1. 读目标、验收和项目约束，弄清相关现状，再追踪必要的真实调用方、数据流、依赖、测试和部署方式。分清哪些是观察到的事实、哪些是推断、哪些还不知道。需求含义不明时先解决需求，不要用技术方案替代产品选择。
2. 列出真正需要决策的问题：职责归属、输入输出和错误语义、状态与并发、权限、兼容性、迁移及外部副作用。只处理其中会影响当前目标或后续工作的部分。
3. 问题确有实质权衡时，比较少量真实可行的方案，说清各自的影响、成本和失败方式。项目里已经适用的机制优先复用。没有必要时直接选最简单的方案，不要为了做比较而编造选项。
4. 确认关键不变量和它的观察方式，并指出哪些部分需要真实环境、数据、设备或外部服务才能验证。数据迁移或发布要说明恢复路径；代码回滚恢复不了数据时，要明确说明。
5. 会影响用户行为、权限、兼容性或长期方向的选择，尚未获得授权时交给用户决定；普通实现细节自行判断。复用会话、已有设计或 ADR，只在确有共享和维护需要时才写文档。

## 停止与交接

报告方案、关键决策依据、权衡结果、验证和恢复的安排，以及还没查清的事。共享决策足以支持实现时停止设计；不要拆票、启动实现或执行外部动作，除非这些工作也在当前请求的授权范围内。
