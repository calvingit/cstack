# Prototype - 制作原型

## 强制约束

- 原型只回答一个具体问题，不当作生产实现。
- 模拟或示意的部分要明确标识；只用隔离数据和已获准的资源。
- 保护已有工作，不把原型默认当最终代码，也不自行删除用户的工作。
- 原型观察不能代替生产系统验收。

## 产物

- **读**：要回答的问题、项目约束、相关代码与数据。
- **写**：原型与观察记录（问题、形式、条件、结论、限制）。不是正式产物；结论影响需求或设计时交回 `clarify` / `design`。
- 需要与其他 Skill 统一产物命名和字段时，调用 `core` Skill；未安装时以本节作为最小可用版本。

## 目标

用尽可能小的成本提高判断的确定性：行为、状态、界面或集成到底该怎么做。

## 选择形式（保真度阶梯）

- **文字或草图**：先厘清概念与边界。
- **可运行逻辑脚本或最小状态机**：验证行为、状态、算法。
- **界面原型（界面桩）或隔离技术试验**：验证交互与集成可行性。
- **真实 Runtime 原生交互展示**：只在需要真实观感时使用。

用户指定交付形式就照办；不强制 HTML、特定框架或持久化。

## 做法

1. 明确原型要回答的问题、要观察的结果和范围；用户已定的选择直接沿用，关键条件缺失就把假设说明白。
2. 把原型和模拟部分明确标识出来；使用隔离数据和已授权的资源。
3. 实际运行或操作相关路径，记录条件、观察结果和还没验证的部分。
4. 结论回到最初的问题；模拟行为只证明原型里的结果，不能说明生产系统已实现或通过验收。

## 停止与交接

说明原型怎么用、结论是什么、限制在哪里。继续实现还是保留原型由用户的请求决定，不强制创建分支、文档或额外状态。
