# Handoff - 工程交接

## 目标

让接手者清楚目标是什么、现在做到哪一步、手头有哪些证据、受哪些约束，以及最小下一步该怎么走。这样才不会重新调查，不会覆盖用户已经做的工作，也不会把计划当成已经完成。

## 方法

1. 先定下交接给谁、接下来要做什么，以及用户指定的交接范围。再读已有的任务资料、当前的代码或仓库状态，需要时读原始结果。把这些内容分成四类：已经发生的事、已经确认的决定、推断，以及还没验证过的事项。
2. 概述目标和范围，点明关键约束，再列出已经完成的工作，以及还没做完或受阻的事项。涉及代码时，要交代候选、基线、还没提交但和本次交接有关的工作，以及已知正在运行的操作。核对不了的状态明确标为未知，也不要去猜其他执行者已经停了。
3. 关键结论要引用能直接找到的文件、命令输出、测试或外部记录，并说明这些记录对什么对象适用、有什么限制。写实际执行的结果，不要复述计划。日志、权限或环境条件有缺失，就把它们留作缺口。
4. 写出最小下一步，让接手者能接着做下去；同时写清这一步依赖哪些决定、现有授权到哪为止、哪些用户状态不能破坏。先前讨论过的方案不能写成已批准设计，提交、合并或生产操作的授权也不要自行扩大。
5. 能复用现有文档和任务记录就复用，记录位置听用户的，或者按项目惯例来。只需要会话交接时，直接在回复里写清楚。不要另建重复的状态库、强制模板或长篇操作日志。

## 停止与交接

交付一份摘要和必要的链接。摘要要能查证，也要和当前状态对得上。交接本身不继续实现，不修改历史，也不通知他人。有哪项事实核对不了，就写出这个缺口，并说明接手者可以怎么查。
