# Handoff - 工程交接

## 目标

让接手者知道目标、当前状态、证据、约束和最小下一步，避免重新调查、覆盖用户工作或把计划误认为已完成。

## 方法

1. 确定接手对象、继续目标和用户指定的交接范围。读取已有任务资料、当前代码或仓库状态及必要的原始结果；区分已经发生的事、已确认决定、推断和未验证事项。
2. 概述目标、范围和关键约束；列出已完成工作与尚未完成或受阻的事项。涉及代码时说明候选、基线、相关未提交工作及已知运行中的操作；无法核对的状态明确标为未知，不猜测其他执行者已经停止。
3. 对关键结论引用能直接找到的文件、命令输出、测试或外部记录，并说明其适用对象及限制。记录实际执行结果而非重述计划；缺失的日志、权限或环境条件保留为缺口。
4. 写出能继续执行的最小下一步、依赖决策、现有授权边界和需要避免破坏的用户状态。不要把先前讨论过的方案写成已批准设计，也不扩大提交、合并或生产操作的授权。
5. 优先复用现有文档和任务记录，按用户指定的位置或项目惯例记录；只需会话交接时直接回复。不要创建重复的状态库、强制模板或长篇操作日志。

## 停止与交接

交付一份可核查且与当前状态一致的摘要及必要链接。交接本身不继续实现、修改历史或通知他人；若某项事实无法核对，写出缺口及接手者可采取的检查。
