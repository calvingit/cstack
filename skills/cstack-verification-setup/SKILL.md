# Verification Setup - 建立项目验证能力

## 目标

让后续执行者知道如何安全启动、操作和观察项目的相关行为。项目已有测试、脚本、CI 和文档优先；不要默认生成新的 Skill 或强制安装框架。

## 方法

1. 确定请求是仅调查、建立新方法还是修复失效方法。读取项目指令、依赖、现有运行命令、测试、CI 和相关入口，区分声明的能力与实际运行过的能力。仅调查时保持只读。
2. 针对目标界面识别：启动与就绪条件；可操作入口；身份、种子数据和依赖；如何观察结果及副作用；版本与构建身份；隔离、资源归属和清理方式。一个项目可包含 UI、API、CLI 和设备等多个入口，不必一次覆盖全部。
3. 将现有方法与需要观察的行为对应起来，指出真实路径、mock 或模拟边界和缺失项。不要因工具名称就声称覆盖真实系统；不要把当前实现行为当作验收预期。
4. 建设获授权时，先复用已有方法，只增加必要脚本、项目说明或测试能力。新增依赖、外部系统和共享资源写操作受用户与项目授权约束；不能为让方法运行而静默修改产品行为或放宽断言。
5. 对新增或修改的方法实际运行最小代表性路径：启动、操作、观察、保留证据、清理自己创建的资源。记录命令、环境、实际结果和未覆盖范围；无法试运行时标为草稿或受阻。

## 停止与交接

报告可复用的方法、前置条件、观察范围、实际试运行结果、清理情况与缺口。已有位置足够时不造新的 Profile 或能力索引。项目方法可用不等于任何任务候选已经通过验收。
