# Impact - 变更影响分析

## 目标

追踪一项已有或拟议变更的真实影响，找出其安全性依赖的关键事实及仍需观察的风险。结果为方案、实现、验证或审查提供依据，不自动替代这些判断。

## 方法

1. 确定变更意图、候选或拟议范围、基线及已知约束。已有变更时检查实际 diff 和工作树；只有方案时标明它尚未实现，不把计划中的行为写成现状。
2. 从受影响入口追踪必要的调用方、数据流和下游消费者，包括公共接口、序列化格式、持久数据、异步任务和外部系统。搜索引用只是起点；检查动态调用、配置和跨语言契约时如有盲区，明确说明。
3. 识别影响判断依赖的少量关键不变量，例如谁能访问、写入是否幂等、旧数据能否读取或失败能否恢复。对每项说明实际证据及其能支持的结论；必要且获准时运行针对性检查，不为证明安全操作真实业务数据。
4. 按触发条件、影响对象和实际后果列出有依据的风险；同时记录已查明不受影响的范围和无法判断之处。区分直接观察、代码推断和待证实假设，不把可能性清单当作已发生缺陷。
5. 指出哪些验收、构建、配置或审查证据可能因变更失效，以及最小可行的补充检查。能证明不受影响的证据可以复用；无法判断的部分需要观察或保留未知。

## 停止与交接

报告基线与范围、受影响路径、关键不变量的证据、已排除事项、剩余风险及检查建议。分析请求默认不修改代码、不执行交付；若证据不足，不宣布变更安全。
