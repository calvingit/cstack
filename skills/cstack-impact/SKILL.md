# cstack-impact · 变更影响分析

## 强制约束

- 分析已有或拟议变更的真实影响；未实现的方案不能写成现状。
- 搜索引用只是起点；动态调用、配置和跨语言契约有盲区，查不到要说明。
- 不把可能性清单当成已发生的缺陷。
- 只做分析时默认只读；不为证明安全去操作真实业务数据。

## 产物

- **读**：变更或方案、实际 diff 与工作树、调用方、数据流、公共契约、持久数据、配置、测试。
- **写**：影响报告（基线与范围、受影响路径、关键不变量证据、已排除项、剩余风险、检查建议、可能失效的证据）。不是正式产物。
- 需要与其他 Skill 统一产物命名和字段时，调用 `cstack-core` Skill；未安装时以本节作为最小可用版本。

## 目标

查清一项变更实际影响到什么，找出决定这项变更是否安全的关键事实，以及仍需继续观察的风险。结果供设计、实现、验证或审查参考，不自动替代这些判断。

## 方法

1. 定变更意图、候选或拟议范围、基线和已知约束。已有变更看实际 diff 和工作树；只有方案时标明未实现，计划中的行为不能当现状写。
2. 从受影响的入口往下追必要的调用方、数据流和下游消费者，公共接口、序列化格式、持久数据、异步任务和外部系统都算。搜索引用只是起点。
3. 找少数关键不变量——谁能访问、写入是否幂等、旧数据能否读出、失败能否恢复——每项说明实际证据和它能支撑的结论。确有必要并获授权时，跑针对性的检查。
4. 按触发条件、影响对象和实际后果列有证据的风险；已查明不受影响的部分和判断不了的地方也一并记下。区分直接观察、代码推断和待证假设。
5. 指出哪些验收、构建、配置或审查证据可能因这次变更失效，以及最小可行的补充检查。能证明不受影响的证据可以继续用；判断不了就保留为未知。

## 停止与交接

报告基线与范围、受影响路径、关键不变量的证据、已排除事项、剩余风险和检查建议。只做分析时默认不改代码、不执行交付。证据不足时，不要宣布这次变更安全。
