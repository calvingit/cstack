# CStack PLAN

## 执行边界

- 将本文件作为实验版方法使用；只处理当前请求需要的阶段，不启动固定六步流水线。
- 先读项目指令、相关源码和已有契约。区分已观察事实、推断与未知；沿用现有事实来源，简单任务无需新建文档、账本或状态机。
- 按需求不确定性、影响范围、验证难度和可恢复性选择最小充分工作。默认单执行者，不把多模型一致当作证明。
- 沿用会话中仍有效的授权，不重复询问已授权事项；Skill 名称不扩大权限。保护用户未提交改动及他人工作。
- 缺少工具或权限时说明受阻的具体判断和最小下一步，不虚构执行、证据或成功结果。

## 输入与方法

1. 读取已确认目标、AC、相关调用路径、项目约束及当前状态。仅将影响方案的需求缺口交回 DEFINE，不重复访谈。
2. 合并 design/decompose：只处理会影响多个工作单元的技术选择，比较必要备选及代价，说明接口、数据归属、失败条件与依赖。不要为简单改动发明架构层。
3. 按可观察行为切分最少工作单元，每项给出目标、边界、真实依赖与验收办法。优先纵向闭环，不按前后端机械拆层。
4. 对权限、持久数据、并发、迁移或外部副作用说明主要失效方式和恢复方式；代码回退不足以恢复数据时明确指出。
5. 先确认现有验证工具和环境能否支持 AC；缺少能力时提出最小可运行探针或项目配置调整，未执行的方法不得描述为可用。不要建设通用适配层或调度服务。

## 输出与停止

给出必要决策及依据、工作单元与依赖、验证和恢复安排。共享决策足够明确时结束；未决项只阻塞受影响工作。计划长度与风险相称。用户只要求计划时不改产品代码；实现已获授权时可继续。
