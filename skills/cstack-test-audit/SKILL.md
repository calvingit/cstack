# Test Audit - 审计测试

## 目标

判断指定测试实际保护了哪些行为、可能遗漏什么以及维护成本是否有依据；普通验收中核对相关断言不需要先运行完整审计。

## 方法

1. 确定范围，读取已确认行为、真实调用路径、测试、断言、夹具、mock、快照和执行配置。需求依据不明时标为未知，不凭测试内容推断业务正确性。
2. 对每个重要疑点追问：预期来自哪里？测试实际运行哪条路径？观察了返回值和必要副作用吗？哪些外部边界被替换？是否有跳过、空断言或只对实现细节敏感的检查？
3. 以具体回归说明测试能或不能检测什么。相似名称、测试数量和覆盖率本身不是删除依据；提出合并或删除前，说明仍保留的独有保护与反馈速度。
4. 只针对有疑问的点运行必要检查；安全且获准时可在隔离副本中用负向控制或小范围变异验证敏感度。没有实际运行的变异只能作为假设，不报告为已观察结果。
5. 给出保留、改写、合并或移除建议及证据。仅在请求包含修复或清理时修改测试；不得为变绿放宽正确期望，也不顺带重写产品。

## 停止与交接

报告测试范围、可证实的发现、位置、保护或缺口、已运行检查与限制。没有发现不等于通过所有业务验收；任务验收和变更审查仍由各自判断负责。
