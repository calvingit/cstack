# CStack BUILD

## 执行边界

- 将本文件作为实验版方法使用；只处理当前请求需要的阶段，不启动固定六步流水线。
- 先读项目指令、相关源码和已有契约。区分已观察事实、推断与未知；沿用现有事实来源，简单任务无需新建文档、账本或状态机。
- 按需求不确定性、影响范围、验证难度和可恢复性选择最小充分工作。默认单执行者，不把多模型一致当作证明。
- 沿用会话中仍有效的授权，不重复询问已授权事项；Skill 名称不扩大权限。保护用户未提交改动及他人工作。
- 缺少工具或权限时说明受阻的具体判断和最小下一步，不虚构执行、证据或成功结果。

## 输入与方法

1. 读取目标、AC、项目指令和相关实现；检查工作树与基线，保护已有改动。只解决会改变实现的缺口，不要求先生成完整规格或设计文档。
2. 故障先复现，再沿调用路径提出可证伪原因并用观察排除；仅诊断请求到原因和限制为止。修复已授权时完成最小必要改动，不顺手扩大范围。
3. 在实现前从业务 AC 确定预期。按任务需要使用 TDD 或现有检查；不要通过删除断言、扩大 mock、跳过测试或降低阈值制造绿色。
4. 运行与改动相称的开发检查，保留命令、结果与限制。修改测试标准须说明业务依据及授权；修复测试自身错误也不能静默改变验收目标。
5. 标识交付候选：提交与基线；有未提交修改时附实际 diff/内容快照标识，覆盖相关未跟踪文件。仅 HEAD 不能代表脏工作树。验证后修改相关内容，要标明旧结果不再覆盖新候选。

## 输出与停止

报告实际改动、候选、开发检查及未验证行为。开发检查不自动等于 AC 全部通过，也不构成合并许可。实现与必要检查完成后交接 VERIFY/REVIEW 所需事实；已授权的连续任务可继续，未获授权的外部写操作不得从实现请求中自行扩张。
