# cstack-handoff · 工程交接

## 目标

让接手者清楚目标、当前进度、证据、约束和最小下一步，避免重新调查、覆盖用户工作或把计划当成已完成。

## 强制约束

- 交接不制造第二份任务状态；能复用现有文档和任务记录就复用。
- 计划不是已经发生的结果；未验证的状态标为未知，不要假设其他执行者已经停止。
- 授权范围要写清，不自行扩大提交、合并或生产操作权限。
- 交接本身不继续实现、不改历史、不通知他人。

## 产物

- **读**：已有任务资料、当前代码或仓库状态、原始结果、授权记录。
- **写**：交接摘要（目标与范围、已完成、未完成或受阻、已确认的决定、推断 / 未知、证据与限制、最小下一步、授权边界）。可放会话回复或项目已有位置；不是正式产物。
- 需要与其他 Skill 统一产物命名、字段或共享判据时，读取 `cstack-core` 的 `ARTIFACTS.md`、`PRINCIPLES.md`、`CRITERIA.md` 对应小节；未安装时以本节作为最小可用版本。

## 交接步骤

1. 确定交接给谁、接下来要做什么、用户指定的范围；读任务资料、当前代码或仓库状态，需要时读原始结果。内容分成四类：已发生的事、已确认的决定、推断、未验证事项。
2. 概述目标与范围，点明关键约束，列出已完成工作和未完成或受阻事项。涉及代码时交代候选、基线、未提交但相关的改动，以及已知正在运行的操作。核对不了的状态标未知。
3. 关键结论引用能直接找到的文件、命令输出、测试或外部记录，说明对什么对象适用、有什么限制。写实际结果，不复述计划。日志、权限或环境缺失就留作缺口。
4. 写出最小下一步，让接手者能接着做；写清依赖哪些决定、现有授权到哪为止、哪些用户状态不能破坏。讨论过的方案不能写成已批准设计。
5. 能复用现有文档就复用，位置由用户指定或按项目惯例；只在会话交接时直接在回复里写清。存在 MAP 或决策工单时引用它们，不复制；跨会话大工作的推进归 `cstack-wayfinding`。

## 完成与交付

把交接摘要和必要链接交给接手者，内容要能查证，并与当前状态一致。核对不了的事实写出缺口，并说明接手者可以怎么查。
