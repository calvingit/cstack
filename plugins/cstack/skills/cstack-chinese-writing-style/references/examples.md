# 改写与审校示例

主文件给出规则，这里放完整的译前译后对照。规则条文见 [SKILL.md](../SKILL.md)，本文件只承担两件事：把抽象规则落到具体句子上，以及记录依赖上下文的单例改写。

## 一、改写模式：一句话里叠了四类问题

原文是一段典型的机翻式产品介绍，四个毛病出现在同一句话里。

原文：

> 对于基于零信任架构的云平台来说，在正式上线之前，对其进行一次全面的风险评估是很有必要的。此外，该平台在面对来自外部的网络攻击时，需要能够保持稳定运行的状态。

改写：

> 零信任架构云平台上线前，务必要完成全面风险评估，确保平台遭遇外部网络攻击时仍能稳定运行。

逐处对照：

| 原文 | 问题 | 改法 |
| --- | --- | --- |
| 对于基于零信任架构的云平台来说 | 介词框架冗余，“对于……来说”是英文 *for/to* 的直译 | 收成名词短语“零信任架构云平台” |
| 对其进行一次全面的风险评估是很有必要的 | 形式主语加泛动词，“是……的”判断句直译 | 改成“务必要完成全面风险评估” |
| 此外 | 逻辑连接词机械对应 *besides/moreover* | 删掉，靠语义自然衔接 |
| 该平台在面对……时，需要能够保持稳定运行的状态 | 范畴词冗余，“……的状态”是英文 *state* 的搬运 | 收成“平台遭遇外部网络攻击时仍能稳定运行” |

四条改法分别对应主文件的句法层与语篇层。改写后一句话读完，读者不必在介词框架和判断句里绕两圈才拿到信息。

## 二、审校模式：原文通顺，问题在概念混用

中文原文本身没有翻译腔，问题出在结构压缩和概念混用，属于审校模式的典型场景。

原文：

> 找出会改变用户可见行为、业务规则、兼容性、权限、验收或交付范围的分歧。将未确认业务选择与普通技术细节分开：后者在现有约束内自行决策。

改写：

> 找出会改变结果的未决选择：可能影响用户可见行为、业务规则、兼容性、权限、验收或交付范围。将业务选择与技术细节分开：业务选择由用户决定，技术细节在现有约束内自行决定。

逐处对照：

| 原文 | 问题 | 改法 |
| --- | --- | --- |
| 分歧 | 本义是意见不合，与下一句“未确认业务选择”指同一对象 | 统一为“未决选择” |
| 会改变用户可见行为、业务规则……或交付范围的分歧 | 六项清单塞进“的”字定语，读者读到最后才拿到中心词 | 冒号引出，分句说明影响范围 |
| 后者在现有约束内自行决策 | “后者”回指悬空，读者要反推指的是哪一项 | 显式对照：业务选择由用户决定，技术细节在现有约束内自行决定 |

## 三、单例改写：答案依赖上下文，不要照搬

下列写法主干是口语，但改成什么取决于它要表达的具体事实。表里给的是改写方向，不是可以全局替换的词表；通用词级映射见主文件的“口语词替换表”。

| 原文 | 依赖的事实 | 改写方向 |
| --- | --- | --- |
| 中间态不能是坏的 | 这里的“坏”指哪个层面上不可用 | 依据实际约束写成“中间态必须可用”，或写明具体不可用的条件 |
| 需求是否有着落 | “着落”既可能指已覆盖，也可能指已确认 | 按实际语义写成“需求是否覆盖”或“需求是否确认” |
| 证据是否扎实 | 指证据充分还是证据可追溯 | 按实际语义写成“证据是否充分”或“证据是否可追溯” |
| 重点在…… | 原句主语是对象，改写后主语成了读者 | 视句子结构调整，可写成“关注……”或“主要问题是……” |

同时提醒一点：替换之后要复查整句主语。把“重点在并发控制”改成“关注并发控制”，句子的主语就从并发控制换成了读者；如果前后文都无人称，改完反而破坏一致性。

## 四、还有几组常见句式

条件句与被动，改写前后并列对照：

| 翻译腔 | 改写后 |
| --- | --- |
| 配置文件在系统启动时被自动加载。 | 系统启动时自动加载配置文件。 |
| 所有请求都会被网关模块进行校验。 | 网关模块校验所有请求。／所有请求均由网关模块校验。 |
| 完成 A 后，且满足 B，才允许执行 C。 | 完成 A 并满足 B 后，方可执行 C。 |

名词化结构，删掉泛动词后句义更直接：

| 翻译腔 | 改写后 |
| --- | --- |
| 对集群进行扩容操作。 | 扩容集群。 |
| 实现数据的实时同步。 | 实时同步数据。 |
| 已授权的工作继续进行。 | 已授权的工作照常继续。 |
| 问题得到解决后再推进后续工作。 | 问题解决后继续推进。 |

长定语与长清单，拆开后中心词才立得住：

| 翻译腔 | 改写后 |
| --- | --- |
| 一个用于在超时后自动重试请求的配置项。 | 该配置项用于超时后自动重试请求。 |
| 一款面向企业用户的支持多维度查询的数据分析工具。 | 一款面向企业的数据分析工具，支持多维度查询。 |
| 处理会影响兼容性、权限、验收等的配置。 | 处理可能影响兼容性、权限或验收的配置项。 |

短句堆叠，合并的前提是仍在讲同一个话题：

> 堆叠：这个接口需要登录。默认返回 30 条记录。支持分页。分页参数优先。没有数据时返回空列表。
>
> 连贯：该接口要求登录后调用，默认返回 30 条记录并支持分页；用户传入分页参数时，以该参数为准。没有数据时返回空列表。

## 五、不能统一的写法

统一之前先验证，前提不成立时统一就是改错。下列三组形式相近、语义不同，两个写法都要保留，并在正文写清区别。

| 写法 A | 写法 B | 区别 |
| --- | --- | --- |
| `git diff A..B` | `git diff A...B` | 两点直接比较两端；三点从共同祖先比较。把三点统一成两点，会把对方分支已有的改动算进本次变更。 |
| `--force` | `--force-with-lease` | 后者带远端校验，统一成前者会丢掉这层保护。 |
| `-f` | `-F` | 前者始终按字符串发送，后者推断类型，往任一方向统一都会送错值。 |
