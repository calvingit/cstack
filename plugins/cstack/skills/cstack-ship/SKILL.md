# cstack-ship · 交付变更

## 目标

按当前候选、有效证据、项目门禁和用户授权，完成所请求的交付。准备、合并、发布是能力分组，不因一句话自动升权。

## 强制约束

- 准备、推送、创建 PR、入队、合并和部署是不同动作；阶段名或 Skill 名不是授权。
- 描述与候选同步：追加提交、扩大范围或更换目标分支后，原标题与原描述都不再对应当前候选。重新核对前不要声称 PR 就绪；描述滞后按交付内容未记录处理。
- 就绪、授权和实际执行结果分开表达。
- `FAIL` / `NOT VERIFIED` 不能改写成 `PASS`；不绕过硬门禁。
- 没有真实动作或证据就明确说明。

## 产物

- **读**：EVIDENCE、项目门禁与分支保护、用户授权、当前候选与基线。
- **写**：就绪与授权判断、实际执行结果（短记录）；不伪造平台状态。
- 职责边界：本 Skill 判断「描述与候选是否同步」以及合并、发布授权；评审意见的逐条处置归 `cstack-pr-feedback`，不因补了内容核对而放宽原有归属。
- 需要与其他 Skill 统一产物命名、字段或共享判据时，读取 `cstack-core` 的 `ARTIFACTS.md`、`PRINCIPLES.md`、`CRITERIA.md` 对应小节；未安装时以本节作为最小可用版本。

## 判断顺序

1. 确定用户要求的结果、已授权动作与对象、目标分支 / 环境、候选和基线；读平台或仓库实际状态、未提交改动、项目规则、已有验收与审查。
2. 判断验收、审查、必需检查和审批是否覆盖当前候选与基线，核对实际受测对象和产物来源。`cstack-verify` 或 `cstack-review` 记为未运行，不等于通过，应记为缺口；`cstack-simplify` 可以跳过。绿色状态、被跳过的检查或模型意见，都不能自动当成业务验收。相关变化后，只有原依据仍然成立才能复用旧结果；不确定就补验或记录为缺口。
3. **Content Readiness** 与 Merge Readiness 分开：前者判断「这个 PR 是否如实描述并包含了当前候选」，后者判断「这个候选能否合并」。四项核对都以平台或仓库实际状态为准，只读命令即可完成：
   - **覆盖**：用 `git log --oneline --name-only <目标分支>..<候选>` 列出每个提交涉及的文件，逐个确认标题或描述里有对应条目；与本需求无关的顺带改动单独成节，不混入功能改动清单。
   - **一致**：本地 HEAD、远端源分支与 MR 记录的候选提交一致，且 MR 的提交条数等于 `<目标分支>..<候选>` 的提交数。存在未推送提交时，即使 MR 状态是 opened，它也不包含全部改动。
   - **基线**：目标分支是否前进过，用 `git log <候选>..<目标分支> --oneline` 确认；再用 `git merge-tree --write-tree <目标分支> <候选>` 做无副作用冲突预检——返回树对象且退出码 0 表示可自动合并，存在冲突时输出列出冲突文件。
   - **边界**：工作区未提交改动是否属于本次交付。不属于的本地绕过或调试改动明确排除，既不提交也不写进描述。
   结论只用三种表述：描述已同步 / 描述滞后（列出缺哪几项）/ 未核对。
4. **Merge Readiness** 与 **Release Readiness** 分开：前者看阻塞缺陷、有效证据、必需 CI、审查状态、分支状态与可回退性；后者看部署配置、灰度、迁移、观测、发布后验证与恢复。合并会自动部署时两者一起评估，但结论仍分开。合并授权不自动覆盖生产环境操作及其副作用；访问不到就标未知。
5. 状态词汇统一：`Content Readiness` / `Merge Readiness` / `Release Readiness`；`GO` / `HOLD` / `NO-GO`；实际结果用「已准备 / 已推送 / PR 已创建 / PR 内容已同步 / 已入队 / 已合并 / 已部署」分别说明。「PR 已创建」不覆盖「PR 内容已同步」。
6. 针对指定候选、目标和观察时点，把技术就绪、授权范围、阻塞与剩余风险分开报告。接受风险要有依据和明确的接受者。
7. 执行条件：用户要求并授权、必要门禁满足、相关副作用在授权范围内，三者同时成立才用现有工具执行。只问真正缺失的决定或权限，已授权的不要重复问。创建 PR 或推送不等于可以合并或部署；项目要求人工批准时遵守。
8. 动作前重读能拿到的候选、目标和关键门禁。平台支持把前置条件绑定到预期候选或版本时，优先使用这种能力；保证不了检查与执行之间条件不变，就说明这个限制。状态变化后重判受影响的证据。
9. 实际结果到平台或工具核对：入队不等于已合并，合并也不等于已部署；失败、未知或进行中都不能说成完成。

## 报告与停止

- 报告候选与目标、内容就绪、技术就绪、授权与副作用、实际执行结果、阻塞、证据和必要恢复安排。
- 写入 PR 标题或描述后，按关键词回读平台返回的正文再报告；`result: success`、HTTP 200 或页面出现新内容，都不等于写入符合预期。解析响应时以工具实际支持的查询参数为准；不支持时改用能读到这些字段的方式。
- 只要求判断时停在判断；要求交付且已授权时，直到得到所请求的结果，或遇到具体阻塞为止。
- 没有真实动作或证据就明确说明。
