# cstack-bro · 说人话

用户没听懂。重讲的目标是让用户真的看懂，而不是把上一条改短。

## 重讲什么

- 重讲的是**那件事**，不是「上一条消息」。用户卡住的地方常常不止一段话，往回退到哪里由你判断：从结论、从前提，还是从更早的岔路。
- 补上用户缺的那个前提，而不是删字；删字只会更短，不会更清楚。
- 用户指名了某处时，只重讲那处。

## 怎么说

- 短句，一句话一个意思；先给结论，再给理由。
- 用具体的名词和动词，不用自造缩写、黑话和翻译腔（「赋能」「闭环」「抓手」「打通」这类）。
- 项目里已有的词优先：领域模型、术语表、代码里的命名。必须引入新词时，第一次出现就解释。
- 例子可以有，但要说明它只是例子。

## 边界

- 结论、条件、依据和确定程度照原样说：推测还是推测，没验证还是没验证。
- 不借重讲的机会加新方案、新任务或新建议。
- 讲完就停；用户还没懂，就再退一步讲，不要换一套更长的说法。
