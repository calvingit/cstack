# cstack-create-project-profile · 建立与更新项目工程档案

## 目标

让后续 Skill 能按需定位项目事实，而不是每次重新发现，也不再各自维护一份过期副本。档案不是一次性初始化：项目约定变化、路径迁移或发现新事实时，用同一套流程更新已有档案，而不是重写整份或另存一份。

## 强制约束

- 只记录**稳定的项目事实**；不存当前需求、任务状态、运行结果、授权、命令、模型选择或 Git 权限。
- 已有档案与已有来源优先：沿用、补齐或修正，不复制、不整份重写；不假定固定路径；不创建空脚手架。
- 写入前展示检测依据和拟写内容，确认后再写。
- 配置本身不授予提交、推送或外部发布权限。
- `AGENTS.md` 与工程档案的写入权归本 Skill；其他 Skill 只提交待并入的片段，不直接写这些文件。

## 产物

- **读**：用于确定 PROFILE 字段的来源——项目指令、README / CONTRIBUTING、现有任务约定、领域与架构文档、验证指南。
- **写**：PROFILE——术语表 / 领域模型位置、验证入口、需求权威来源、既有架构决策（ADR）位置、任务文档存放约定、界面设计系统位置；字段名和顺序固定，见下方示例。首次是建立，之后是增量更新同一份档案。位置按顺序选：项目指令里已链接的档案 → 项目已有的工程档案位置 → 都没有才新建 `.agents/profile.md`。`AGENTS.md`（或项目等效的指令文件）只放链接与读取条件。
- 需要与其他 Skill 统一产物命名、字段或共享判据时，读取 `cstack-core` 的 `ARTIFACTS.md`、`PRINCIPLES.md`、`CRITERIA.md` 对应小节；未安装时以本节作为最小可用版本。

## 核对现有档案

- 先读适用指令与协作规则，再按 PROFILE 字段逐项查找：术语表 / 领域模型位置、验证入口、需求权威来源、ADR 位置、任务文档存放约定、界面设计系统位置。
- 已有条目不等于仍然成立：核对链接能否打开、路径是否迁移、约定是否已被新做法取代；过期项按证据修正或标为失效，不照抄旧档案。
- 同时核对 Git 状态，记录位置、证据和适用范围。
- 把候选标为 confirmed / inferred / missing / conflicting；目录或工具存在，不等于有权威或真的可用。

## 只记录稳定事实

- 记录位置与策略：术语表在哪、验证入口是什么、需求权威来源是哪一种、ADR 放哪、任务文档放哪、界面设计系统放哪。
- 具体验证方法留在现有指南或本地验证资料里；PROFILE 只放链接与摘要。界面设计文档的正文不写进档案。
- 不预建空的任务目录、术语表、ADR、验证 Harness 或界面设计文档。

## 示例（示意）

示例固定**字段名、字段顺序和一行一位的粒度**；路径、项目名和篇幅按项目实际替换，它不是要照抄的模板。

`AGENTS.md` 里只加链接与读取条件：

```markdown
- 工程档案：`.agents/profile.md`（做需求、验证、设计或任务记录前先读）
```

PROFILE 沿用 `cstack-core` 的六个字段名，每项写「位置 + 一句策略」，不写方法正文：

```markdown
# 工程档案

- 术语表 / 领域模型位置：`docs/glossary.md`；领域概念在 `docs/domain/`，命名以术语表为准。
- 验证入口：`docs/runbook.md` 的「本地运行」一节；冒烟命令 `make smoke`，证据放 `artifacts/evidence/`。
- 需求权威来源：外部工单系统 ABC 项目；与 `docs/prd/` 冲突时以工单当前版本为准。
- 既有架构决策（ADR）位置：`docs/adr/`，文件名 `ADR-<序号>-<slug>.md`。
- 任务文档存放约定：`docs/tasks/<yyyy-mm-dd>-<slug>.md`；没有就留空，不预建目录。
- 界面设计系统位置：`DESIGN.md`；做界面、改主题或做视觉审查前先读。没有就不填，不预建文件。
```

更新已有档案时沿用这六项和同样的一行一位写法，不另起字段名、不再分一层子标题。还没有「界面设计系统位置」这一行时补上：有文档或调用方交来了片段就写路径，否则留空，不编造路径，不预建文件。

## 写入

1. 展示检测依据、拟写 PROFILE、`AGENTS.md` 条目、需要迁移的旧配置，以及与现有档案的差异。
2. 已有明确值沿用；仓库证据无法确定的重大选择问一次；调用方已给的确认不再重复问。
3. 更新时只改有证据变化的字段，保留未受影响的确认值与未决项。
4. 迁移旧的内嵌配置时，保留确认值与未知字段，然后移除旧块，不留下两份活跃副本。
5. 重复设置同一配置应等同于空操作，不产生重复条目或仅格式上的变化。
6. 重读改动文件，核对路径和链接，检查 diff。

## 报告与停止

- 报告变更条目（新建或更新）、迁移情况、确认值、留给后续处理的项，以及未解决的冲突。
- 文件存在不代表 Runtime 已加载它，也不代表验证方法已经实际运行过。
- 不提交、不推送，除非获授权。
