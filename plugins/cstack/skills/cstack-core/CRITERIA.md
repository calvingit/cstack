# CStack 共享判据

> 由 [SKILL.md](SKILL.md) 索引。这里放**跨 Skill 复用的判断尺子**：怎样算证明到、怎样算可比、怎样算有效测试、问题怎样分级与处置。
> 它不规定方法步骤，也不替代各 Skill 自己的完成条件；只保证同一个判断在不同 Skill 里用同一套标准。

## 怎么用

- 需要判断「证据够不够」「两次测量能不能比」「这条测试有没有用」「这个问题该不该阻塞」时，读对应小节。
- 各 Skill 内嵌一句话版本；只有口径可能不一致或需要分级时才回到这里。
- 判据不扩大授权：判据成立不等于获准修改、合并或发布。

## 证明层级

判断一条安全事实或风险是否成立时，从低到高：

| 层级 | 做到什么 | 单独是否成立 |
| --- | --- | --- |
| 1 | 口头断言；搜索没有结果 | 不成立 |
| 2 | 定位到具体 `file:line`，或所依赖库的源码与固定版本 | 只是线索 |
| 3 | 沿失败路径推演到不可达 | 可以成立，须写明推演前提 |
| 4 | 运行真实代码：脚本或测试调用应用实际依赖的同一库、同一函数 | 通常够用 |
| 5 | 在真实运行环境复现或证伪 | 结论依赖运行时序、外部系统或部署环境时必须到达 |

- 停在哪一层要写明。只列调用方、只写报告、只凭搜索无结果，都到不了第 4 层。
- 安全结论与风险结论方向相反：安全结论要证明失败路径不可达，风险结论要证明失败路径可达。两者用同一套层级，都要写明停在哪一层。
- 判断一个问题能否推翻，也用同一套层级：够不到第 3 层就保留为疑点，不判成立，也不判排除。

## 可比基线

两次测量只有下列条件一致才能比较：候选与版本、设备或环境、构建模式、数据规模与负载、测量工具与口径。

- 差异落在测量波动范围内，不构成提升或回退。
- 条件变了就重测或标「不可比」，不把两次不可比的数据相减。

## 测试有效性

一条测试有效，指它保护可观察行为，并且两个方向都成立：

- 改坏该行为时，测试变红；
- 只调整内部实现、行为不变时，测试仍绿。

- 空断言、只断言数据结构形状、复制实现算法、过度 mock、快照掩盖真实变化，都不满足第一个方向。
- 覆盖率不是有效性；没跑过的变异或负向控制只能算假设。

## 问题分级与处置

严重度描述后果，不描述工作量：

| 级别 | 含义 |
| --- | --- |
| `P0` | 影响面广且后果严重：数据丢失、权限绕过、大范围不可用 |
| `P1` | 严重但影响有限，或存在明确规避路径 |
| `P2` | 局部可修复的缺陷 |
| `P3` | 可选改进 |

处置独立于严重度：

- **本次必修**：本次引入或加重的问题。
- **后续项**：与本次无关的旧问题、可选改进；记录但不阻塞。
- **可接受风险**：由有权方明确接受，记录依据与接受者；不得把 `FAIL` / `NOT VERIFIED` 改写成 `PASS`。

严重度与「是否阻塞本次」是两个决定：`P1` 可以因为不在本次范围而不阻塞，`P3` 也可以因为违反已确认契约而必修。
