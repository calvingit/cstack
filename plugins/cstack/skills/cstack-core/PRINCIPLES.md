# CStack 共享内核

> 这里是 `cstack-core` Skill 的判断强制约束与产物词汇，由 [SKILL.md](SKILL.md) 索引。
> 它只提供共享词汇与强制约束，不是独立任务方法；其他 Skill 需要与共享词汇保持一致时读取 `cstack-core` 的对应文件；`cstack-core` 仅手动触发。

## 怎么用

1. 安装整套 Skill 时，把 `cstack-core/` 与各 Skill 目录一起复制；各 Skill 在需要统一产物命名、字段或 ID 时读取本目录。
2. 只安装单个 Skill 时，不需要本目录：该 Skill 的「强制约束 / 产物」小节已覆盖它自己的职责，能独立运行。
3. 本目录不规定文件名、模板、执行顺序或运行状态。它只固定两件事：**不可违反的判断强制约束** 和 **产物叫什么、字段有哪些**。

## 判断强制约束

这些强制约束适用于所有 Skill，没有例外；这里不解释方法细节。

### 范围

1. 工作不超出当前已确认的目标与范围。
2. 不覆盖、不吞并、不静默改写不属于当前任务的既有改动。

### 认知

3. 区分已观察的事实、推断和未知；不编造来源、能力或执行结果。
4. 判断事实时使用与当前对象、版本和条件相匹配的依据；来源冲突未解决时，不把任何一方当成已确认事实。
5. 派生记录必须能追溯到事实来源，不能变成另一套互相冲突的权威。

### 决策

6. 超出已授权范围、会改变需求或契约的未决选择，交回有权决定的人。
7. 变更只改负责该事实的产物，再重新判断受影响的下游环节；未受影响的有效结论不因流程重启而作废。

### 授权

8. 任务、工具、交接记录或 Skill 的存在本身不增加授权；委派与调用只能收窄，不能扩大权限。
9. 只在获准的资源范围内执行、写入和清理；外部写入结果未知时，先确认副作用可控，再决定是否重试。

### 证据

10. 完成声明必须对应当前确认的结果和条件，并有与风险及声明范围相称的证据。
11. 预期结果来自确认的需求、契约或独立依据，不能反过来由待验证的实现来定义。
12. 证据只支持实际观察到的行为和边界；门禁通过、工具成功或自述，都不能证明未覆盖的条件。
13. 工作状态与验证状态分开写。工作状态只说明做到哪一步、覆盖哪些范围；验证状态只说明检查是否执行、结果如何、覆盖到什么程度。代码改完不等于验收通过。
14. 检查状态按执行情况区分：整项检查没有启动的记为「未运行」；确定某项检查没有执行的记为「未执行」并说明原因；执行情况或结果没有记录的记为「未确认」。三者都不等于通过，只有证据充分才记为通过。
15. 声明任务完成前，验收和审查都必须实际运行；简化可以跳过，但跳过不等于验收或审查已通过。改动大小不能省掉验收或审查。
16. 检查失败必须记为失败，并给出可复核的结果，不能改写成未验证或「基本通过」。
17. 文档资料、静态代码、模拟结果和真实环境运行要分开说明，不能互相替代。

### 恢复

18. 接管重叠写入前，先确认原写入方已停止，或有足以防止冲突的隔离。
19. 观察到的缺陷按未变契约修正；环境、权限或依赖缺口先解决再重试；契约冲突交回负责方。

## 产物词汇

6 类权威产物、字段与 ID 约定见 [ARTIFACTS.md](ARTIFACTS.md)。一句话：**一类事实只有一个权威产物，下游按 ID 引用，不复制内容；产物可以省略，但省略不等于可以凭空假设。**

跨 Skill 复用的判断尺子见 [CRITERIA.md](CRITERIA.md)：证明层级、可比基线、测试有效性、问题分级与处置。判据统一不改变授权，也不把「够不够」变成「准不准」。
