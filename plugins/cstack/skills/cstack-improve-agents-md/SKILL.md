# cstack-improve-agents-md · 建立与更新项目级 Agent 指令

## 目标

把 `AGENTS.md`（或项目等效的指令文件）写成供 Coding Agent 执行任务的简明指南：只放有仓库依据的稳定规则、指针和读取条件；权威内容留在项目原有位置（如 `docs/`、CONTRIBUTING、架构文档）。

审查或建议任务只报告；创建、优化、修复或更新任务执行最小修改。

## 强制约束

- 只在用户手动触发时运行；审查或建议只报告，不改文件。
- 只放有仓库依据的稳定规则、指针和读取条件；权威内容留在原位置，不复制正文。
- 删除规则可能改变预期行为，而仓库证据无法消除歧义时，先向用户确认。不误删安全规则或由真实故障沉淀的约定。
- `AGENTS.md` 正文的写入权归本 Skill；PROFILE 的写入权归 `cstack-create-project-profile`。已有档案时只保留入口与读取条件，不复制档案正文，也不迁移、重建或重新配置 PROFILE。
- 只维护标准 `AGENTS.md` 和标准 Markdown。跨上下文职责审查需要时，告诉用户自行使用 `context-audit`，不代为拉起。配置本身不授予提交或推送权限。

## 产物

- **读**：从仓库根目录到当前工作目录适用的 `AGENTS.md`、覆盖文件和工具入口；清单文件、锁文件、任务运行器和 CI；README、CONTRIBUTING、架构决策、策略及代表性代码；已有 PROFILE（由 `cstack-create-project-profile` 写入，默认 `.agents/profile.md`，或以 `AGENTS.md` 标明的路径为准）。
- **写**：`AGENTS.md`（或项目等效的指令文件）的正文。已有 PROFILE 时保留其入口与读取条件，不改档案本身。`cstack-create-project-profile` 负责写入或更新档案指针这一条。
- 需要与其他 Skill 统一产物命名、字段或共享判据时，读取 `cstack-core` 的 `ARTIFACTS.md`、`PRINCIPLES.md`、`CRITERIA.md` 对应小节；未安装时以本节作为最小可用版本。`AGENTS.md` 不是第 7 类产物：唯一写入者是本 Skill，不进入共享产物链。

## 工作流程

1. 从仓库根目录到当前工作目录，找出适用的 `AGENTS.md`、覆盖文件和工具入口，核对优先级与发现方式。
2. 用清单文件、锁文件、任务运行器和 CI 核对命令，从 README、CONTRIBUTING、架构决策、策略及代表性代码确认项目约定，同时检查生成标记、迁移记录和已发生故障。
3. 按下面的内容标准，将指令归为保留、改写、迁移或删除，处理冲突、过时信息、重复维护和适用范围错误。
4. 起草或应用最小差异，准确的表达原样保留。迁移必要内容时确认其权威位置和入口仍可发现。
5. 检查最终差异：逐条确认指针指向的文件和章节存在、命令可运行或有依据、根目录与子目录之间没有重复或互相矛盾的规则。环境允许时运行相关安全命令，否则说明只做了静态检查。根目录 `AGENTS.md` 以 100 行左右为参考，过长会被部分工具截断；超出时优先把细节迁到权威文档并改成指针，不为凑行数删安全规则。

## 内容标准

指令应长期稳定、可执行、适用于当前范围，并能避免重复劳动或实际错误。只适用局部的规则须在确认发现方式后缩小范围。

| 处理 | 内容 |
| --- | --- |
| 保留 | 会影响任务处理的项目定位、非直观工作区边界、准确命令及前置条件、先局部后全仓检查的顺序、项目架构约束、规范路径、生成或受保护文件、安全与迁移风险、工具不能保证的完成条件。 |
| 改写或迁移 | 长篇示例、完整目录树或依赖清单、可可靠搜索获得的事实、与权威文档重复的说明。用稳定路径和短导航替代副本。 |
| 删除 | 通用口号、过时命令和路径、假设性防护、临时计划与任务状态、会话记录或个人偏好，以及已由仓库工具或所有目标运行环境可靠保证的重复规则。 |

`MUST`、`NEVER`、`ALWAYS` 只用于安全、数据丢失、外部契约或有证据的反复故障，其他规则直接写清要求与适用范围。

## 适用范围与跨工具兼容

- 仓库级规则放在根目录，局部规则只补充或覆盖较窄范围，不复制根规则。所有工作都需要遵守的安全和验证规则不能藏在部分启动位置无法读取的子目录中。
- 多包或多应用仓库在根目录放一张子项目表，写明「修改 `<path>` 前先读 `<path>/AGENTS.md`」；子目录文件只写本范围特有的规则，离代码越近的文件优先。
- 只维护标准 `AGENTS.md`，使用标准 Markdown，不使用 `<important if="...">` 等特定模型的 XML 标签。
- Claude Code v2.1.277 起直接读取 `AGENTS.md`，版本更低时提示用户升级，不新建 `CLAUDE.md`。工作目录或上级目录存在 `CLAUDE.md`、`CLAUDE.local.md` 时，Claude Code 只读它们而不读 `AGENTS.md`：只写 `@AGENTS.md` 的文件建议删除，有实际内容的先报告，经用户确认再合并。
- 创建文档或调整结构时，读取[默认结构](references/default-structure.md)。
- 若项目已有 PROFILE（由 `cstack-create-project-profile` 写入，默认 `.agents/profile.md`，或以 `AGENTS.md` 标明的路径为准），`AGENTS.md` 只保留入口与读取条件，不复制档案正文。发现旧的档案嵌入块或过期路径时报告冲突，不在本 Skill 里迁移或重建档案。跨上下文职责审查需要时，告诉用户自行使用 `context-audit`，不代为拉起。

## 输出

审查时按影响列出问题、证据和最小建议。修改时说明文件与关键规则的保留、迁移、改写或删除，报告实际检查、未验证项和运行环境兼容性限制。
